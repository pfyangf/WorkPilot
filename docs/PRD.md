# WorkPilot 产品需求文档（PRD）

- 文档版本：v2.0
- 日期：2026-10-22
- 状态：实现基线
- 产品代号：WorkPilot
- 目标平台：Windows 10/11 主工作台；Android 与 HarmonyOS 手机配套端
- 语言：简体中文优先
- 技术决策：`docs/adr/0001-shared-rust-core.md`

v1.0 只面向 Windows，并把实现预设为桌面脚本应用。v2.0 保留原有任务、日志、日报和安全规则，平台改为多端。业务核心见《技术设计文档》。早期 Python 实现方案已废弃。

## 1. 背景与目标

日常工作信息分散在任务清单、桌面文件、AI Coding 工具会话和日报中。用户需要手动汇总进展，容易遗漏持续性任务，也容易把「启动了某项操作」误记为「操作已成功完成」。

WorkPilot 建立轻量、可追溯的个人工作闭环：

1. 维护今日任务、持续任务、状态和每日进展。
2. 汇总手工记录与 AI Coding 工具事件，生成可编辑、可审核的日报。
3. 在 Windows 上以可预览、可撤销的方式整理桌面文件和快捷方式。
4. 支持托盘常驻、快捷打开和窗口布局辅助。
5. 用统一接口对接云端大模型，后续逐步接入 AI Coding 工具。
6. 手机端查看和快速记录，不操作电脑上的文件和命令。
7. 后续在已授权设备之间同步，而不是把桌面数据库直接暴露给手机。

### 1.1 产品原则

- 本地优先：任务、日志、规则和日报默认先保存在本机。
- 人工可控：AI 负责归纳与建议，不替用户确认事实。
- 可追溯：日报中的进展应能回溯到任务、日志或工具事件。
- 轻量务实：面向个人和小团队，不引入微服务、多租户和复杂权限系统。
- 安全优先：文件移动先预览。默认不自动删除文件。
- 渐进式集成：先完成 Windows 上的任务与日报，再做手机配套、同步、桌面整理和 Coding 工具。

## 2. 目标用户与典型场景

### 2.1 目标用户

需要管理个人工作、使用 AI Coding 工具并定期写日报的开发者或小团队成员。主要在 Windows 上工作，用 Android 或 HarmonyOS 手机做查看和快速记录。

### 2.2 核心场景

- 开始工作时查看今日任务，将任务设为进行中。
- 处理跨多天持续任务，每天追加进展而不覆盖历史。
- AI Coding 工具完成一段工作后，将会话摘要关联到任务。
- 下班前按日期生成日报，检查来源、编辑措辞并导出 Markdown。
- 桌面文件过多时按规则分类，先预览再执行；误操作通过操作历史恢复。
- 应用在系统托盘运行，随时快速新增任务或打开今日工作台。
- 离开电脑时在手机上查看任务、追加日志或轻量修改日报。

## 3. 范围与版本规划

产品优先级：P0 是 Windows MVP 必须交付的能力；P1 是 Windows 后续能力；手机端和同步按实施阶段交付，不提前并入 P0。

实施阶段以《技术设计文档》为准：

| 阶段 | 用户可感知的范围 |
|---|---|
| Phase 0 | 无界面。只验证共享业务规则 |
| Phase 1 | 本节 MVP，仅 Windows |
| Phase 2 | Android 配套功能 |
| Phase 3 | HarmonyOS 配套功能 |
| Phase 4 | 跨设备同步 |
| Windows 后续 | 桌面整理、Coding 工具采集 |

### 3.1 MVP（Phase 1，仅 Windows）

1. 主窗口、托盘菜单、设置页。
2. 本地 SQLite 与迁移。
3. 项目和任务：创建、编辑、状态流转、优先级、截止日期、持续任务。项目页可以后做，任务允许不关联项目。
4. 每日工作日志：按日期追加、关联任务、记录来源。
5. 日报：按日期读取任务变更和工作日志，调用可配置模型，生成可编辑 Markdown。
6. 日报审核、保存、复制和导出 `.md`。已编辑正文不得被重新生成静默覆盖。
7. 基础搜索、异常提示、日志文件和数据备份。
8. LLM Provider 抽象，以及至少一个 OpenAI-compatible 提供方。

### 3.2 手机配套（Phase 2 Android，Phase 3 HarmonyOS）

1. 查看任务列表和详情。
2. 快速新增任务。
3. 快速记录工作日志。
4. 查看任务进度。
5. 查看和轻量编辑日报。
6. 查看最近同步时间和待同步状态。同步服务未完成时，状态显示为未连接，不显示伪造的成功时间。
7. 查看用户授权后同步过来的 Coding 工具进度摘要。

手机端不整理 Windows 桌面文件，也不在电脑上执行 Coding 工具命令。

HarmonyOS 若无法调用本机 Rust 模块，改为使用 Phase 4 的 HTTPS API。验证完成前，不把原生桥接写成可用功能。

### 3.3 Windows 后续（P1）

- 桌面文件扫描、分类规则、预览、执行、操作历史和可恢复移动。
- 快捷方式整理。
- 全局快捷键。注册冲突时告知用户。
- 窗口布局保存和恢复的可行性验证。不支持或恢复失败的窗口要明确标出。
- Coding 工具事件接入，优先 1–2 个工具。自动采集必须由用户开启，并提供关闭和清理入口。

### 3.4 跨设备同步（Phase 4）

- 身份认证、设备授权和设备撤销。
- 增量同步、幂等提交、网络失败重试、冲突检测。
- 敏感字段过滤。

同步对象是用户自己的已授权设备，不是多用户协作空间。

### 3.5 暂不纳入

- 多用户协作、多租户、服务端权限体系。
- 自动提交代码、自动合并 PR、自动发布。
- 无人值守批量删除或覆盖文件。
- 保证所有 Windows 版本和显示器上都能精确恢复任意桌面图标位置。
- 自动判定代码质量或测试是否通过。
- 把 AI Coding 工具的内部数据当作稳定公共 API。
- 手机直接打开 Windows 本地 SQLite 文件。
- 默认将 Windows 桌面服务暴露到公网。
- 默认同步 AI 密钥、访问令牌、原始 Coding 会话、完整文件路径或本地文件内容。

## 4. 功能需求

### 4.1 工作台与托盘

**FR-001（P0）主工作台**

- 显示当天日期、今日任务统计、最近更新的任务、最近日报。
- 支持进入任务、日志、日报、设置页面。
- 空数据时显示明确的引导操作。

**FR-002（P0）系统托盘**

仅 Windows。

- 提供显示或隐藏主窗口、快速新增任务、打开今日工作台、退出应用。
- 关闭主窗口默认最小化到托盘。退出必须有明确入口。
- 托盘初始化失败时，应用仍可使用，并显示可理解的提示。

**FR-003（P1）快捷操作**

- 可配置全局快捷键，例如快速新增任务或显示窗口。
- 快捷键注册冲突时告知用户。

### 4.2 项目与任务

**FR-010（P0）项目**

- 字段：名称、描述、状态、创建时间、更新时间。
- 支持新增、编辑、归档。归档项目不出现在默认活跃列表中。
- MVP 允许任务不关联项目。

**FR-011（P0）任务**

- 字段：标题、描述、状态、优先级、开始日期、截止日期、项目、是否持续任务、创建时间、更新时间、完成时间。
- 状态：待处理（`todo`）、进行中（`in_progress`）、受阻（`blocked`）、已完成（`done`）、已取消（`cancelled`）。
- 支持创建、编辑、搜索、筛选、排序和状态变更。
- 已完成任务再次打开时，清除完成时间。
- 状态变化写入任务事件历史。
- 标识在所有设备上使用同一个 UUID，不使用数据库自增 ID。

**FR-012（P0）持续任务**

- 持续任务跨日期保留，不因日报生成而自动关闭。
- 每天的进展追加到工作日志，不覆盖任务描述或历史日志。
- 今日任务列表能显示持续任务的最新进展。

**FR-013（P0）子任务**

- 任务可以包含子任务。MVP 限制为一层。
- 父任务完成时，如果仍有未完成子任务，提示用户确认。不得自动把所有子任务标记完成。

**FR-014（P0）任务事件**

- 记录状态变更、标题或描述修改、关联项目变更、完成和重新打开。
- 事件至少包含发生时间、事件类型、简短说明和来源（`manual` / `import` / `integration`）。

### 4.3 工作日志

**FR-020（P0）每日进展记录**

- 用户可在任务详情或日志页追加进展。
- 字段：日期、内容、关联任务（可选）、来源类型、创建时间。
- 允许修改和删除手工录入的日志。修改和删除留下审计记录。
- 新进展不覆盖旧进展。

**FR-021（P0）日志来源**

- 来源类型包括 `manual`、`coding_tool`、`system`、`ai_generated`。
- AI 生成内容保留来源字段，不能改成手工事实。

### 4.4 日报中心

**FR-030（P0）生成日报**

- 用户选择日期后生成日报。
- 生成前显示输入摘要：任务状态和事件、当日工作日志、已关联的 Coding 事件（接入之后）。
- 可选择是否纳入进行中任务、受阻任务、已完成任务和工具会话摘要。
- 模型失败时保留输入数据和已编辑正文，允许重试或手工编辑。

**FR-031（P0）日报内容结构**

- 今日完成
- 进行中和持续推进
- 问题与阻塞
- 后续计划
- 需要确认的事项
- 不适用的章节省略，不生成无意义占位句。

**FR-032（P0）事实准确性**

- 只根据输入材料总结，不捏造任务、结果、数字、测试结论或提交记录。
- 「已启动测试」不能改写成「测试通过」。
- Git 提交、文件变更或 Coding 会话结束不等于任务完成。
- 不确定的结果标记为「待确认」。
- 生成结果可编辑，并显示来源。
- 日报生成不自动修改任务状态。

**FR-033（P0）保存与导出**

- 每个日期可保存多个版本，默认展示最近版本。
- 支持编辑、保存、复制到剪贴板、导出 Markdown。
- 用户编辑并保存后，再次生成不得覆盖该正文。新的生成结果另存为新版本。
- 文件名建议 `YYYY-MM-DD-日报.md`。同名文件存在时询问覆盖或生成新文件。
- 导出失败时提示错误，原有日报内容保持不变。

**FR-034（P1）模板**

- 可配置日报标题、章节和语气。默认使用简洁、客观的中文工作汇报。

### 4.5 大模型配置

**FR-040（P0）Provider 抽象**

- 模型调用封装为统一接口。UI 不直接调用厂商 SDK。
- MVP 至少支持一种 OpenAI-compatible Chat Completions API。
- 配置项：提供方名称、API Base URL、模型名、API Key、超时时间、最大输出长度。
- API Key 存入该平台的系统安全存储。数据库只保存凭据引用，不存明文密钥。
- 允许测试连接。错误信息不得泄漏密钥。

**FR-041（P0）数据提示**

- 调用前说明将发送给第三方模型的内容类别。
- 默认只发送生成日报所需的任务和日志摘要，不发送桌面文件内容。
- 不自动上传源码、完整本地路径、密钥或环境变量。
- 对可能包含密钥的文本做基础脱敏。用户可以关闭云端生成，改为手工编辑。

### 4.6 桌面整理（P1，仅 Windows）

**FR-050（P1）扫描**

- 只扫描用户明确选择的路径。默认读取 Windows 当前用户桌面路径。
- 扫描结果包含名称、类型、扩展名、大小、修改时间和路径。
- 不读取文件内容。默认不递归，除非用户开启。

**FR-051（P1）分类规则**

- 支持按扩展名、名称关键字和文件类型分类。
- 用户可新增、编辑、启停和调整优先级。
- 冲突规则有确定的优先级，并在预览中解释。

**FR-052（P1）预览与执行**

- 执行前展示源路径、目标路径、操作类型和冲突。
- 默认只允许移动或创建分类目录和快捷方式，不提供自动删除。
- 同名冲突默认跳过。只有用户明确选择后才允许重命名或覆盖。
- 批量执行必须由用户确认。

**FR-053（P1）操作历史与恢复**

- 记录每个文件操作的源路径、目标路径、时间、结果和错误。
- 对成功移动提供撤销。目标文件已被外部修改或源位置被占用时停止，并说明原因。
- 不承诺外部进程、网络驱动器或权限变化后都能恢复。

**FR-054（P2）窗口布局**

- 可保存当前能检测到的窗口位置和大小，并尝试恢复。
- 恢复前显示窗口清单。
- 多显示器、权限、受保护窗口和窗口状态变化可能导致失败。失败项必须报告。

### 4.7 AI Coding 工具集成（P1，仅 Windows 采集）

**FR-060（P1）统一事件模型**

- 会话开始和结束、状态变化、工具通知、摘要、文件变更摘要、命令结果映射为统一结构。
- 每条事件包含工具名称、会话 ID、时间、事件类型、摘要、来源位置（如可得）和状态。
- 不保存不必要的完整提示词、源码或终端输出。

**FR-061（P1）接入策略**

- 优先使用工具官方 CLI、Hooks、事件流或公开 API。
- 每个工具独立适配器。适配器故障不影响任务和日报。
- 无法稳定读取时，提供手动导入 Markdown 或 JSON。
- 不通过未授权注入、绕过权限或抓取敏感数据的方式接入。

**FR-062（P1）任务关联**

- 用户可将 Coding 会话关联到任务。
- 自动推荐必须允许人工确认和修改。
- Coding 事件默认只作为日报素材，不自动改变任务状态。

手机端只显示用户授权同步后的进度摘要。

### 4.8 同步状态（Phase 4 完成后生效）

**FR-070（Phase 4）设备与同步**

- 用户登录并授权设备后，才能上传和下载自己的任务、日志和日报。
- 界面显示最近成功同步时间和仍待同步的数量。
- 冲突时保留双方版本信息，不静默丢弃用户编辑过的日报。
- 用户可撤销某台设备。撤销后该设备不能继续同步。
- Phase 4 完成前，手机端的同步区域显示未连接。

## 5. 页面与交互

### 5.1 Windows 主导航

- 工作台
- 任务
- 工作日志
- 日报
- 桌面助手（P1，未实现时不显示为可用）
- Coding 中心（P1，未实现时不显示为可用）
- 设置

### 5.2 手机导航

- 任务
- 记录日志
- 日报
- 同步状态

不提供桌面整理和本机 Coding 命令入口。

### 5.3 日常工作

1. 打开应用，查看今日任务。
2. 创建或选择任务，变更状态。
3. 工作过程中追加进展。
4. 接入 Coding 工具后，查看会话并关联任务。
5. 选择日期生成日报。
6. 检查来源和事实状态。
7. 编辑并保存或导出 Markdown。

### 5.4 桌面整理

1. 选择桌面目录并扫描。
2. 选择规则并查看预览。
3. 处理目标路径冲突。
4. 用户确认执行。
5. 查看执行结果和操作历史。
6. 必要时撤销成功操作。

## 6. 非功能需求

- **NFR-001 稳定性：** 文件系统异常、模型超时或某个适配器异常不得导致整个应用崩溃。
- **NFR-002 数据安全：** 默认本地存储。API Key 不得明文进入 SQLite、日志或导出文件。
- **NFR-003 可恢复性：** 提供手动备份和恢复数据库。恢复前备份当前数据。
- **NFR-004 可测试性：** 业务规则位于共享核心，不依赖 UI，并用自动化测试覆盖。
- **NFR-005 性能：** 普通任务列表在数千条记录下保持可用。文件扫描显示进度，避免阻塞界面。
- **NFR-006 可维护性：** 一个 workspace 内的少量模块。统一模型、配置、日志和错误处理。
- **NFR-007 隐私：** 发往云端的数据最小化，由用户手动触发。
- **NFR-008 可访问性：** 常用操作有可见按钮，错误信息可理解。
- **NFR-009 多端边界：** 手机不访问 Windows 数据库文件，不执行电脑上的文件整理和 Coding 命令。

## 7. 验收标准

### Phase 0

- [ ] 共享核心可以运行领域测试。
- [ ] 任务状态、日志追加和已编辑日报保护有自动化测试。
- [ ] 兼容性记录只包含实际执行过的命令。
- [ ] 没有把 JNI、NAPI、托盘或同步写成已完成。

### Windows MVP

- [ ] 首次启动创建本地数据库并显示空状态引导。
- [ ] 可创建任务，变更状态，重启后仍然存在。
- [ ] 可创建持续任务，并按日期追加多条进展。
- [ ] 任务状态变更产生事件历史。
- [ ] 选择日期后可查看日报输入摘要并触发生成。
- [ ] 模型失败时可重试，已编辑内容仍在。
- [ ] 对已编辑日报重新生成时，原文不被覆盖。
- [ ] 日报可编辑、保存、复制和导出 Markdown。
- [ ] 日报来源可追溯到任务、日志或工具事件。
- [ ] API Key 不以明文出现在数据库和日志中。
- [ ] 模型请求不冻结界面。
- [ ] 任务、日志、日报和 Provider 有自动化测试。

### 手机配套

- [ ] 可查看任务、新增任务、记录日志、查看和轻量编辑日报。
- [ ] 同步未实现时显示未连接。
- [ ] 没有桌面整理和远程执行 Coding 命令的入口。

### 桌面整理（P1）

- [ ] 扫描不改变文件。
- [ ] 预览显示每个计划操作的源和目标。
- [ ] 执行前必须用户确认。
- [ ] 同名冲突默认跳过。
- [ ] 成功移动有操作记录，满足条件时可撤销。

### Coding 集成（P1）

- [ ] 适配器故障不阻断手工任务和日报。
- [ ] 事件带来源工具和时间。
- [ ] 自动关联任务需人工确认。
- [ ] 不把会话结束或代码提交解释为任务完成。

### 同步（Phase 4）

- [ ] 未授权设备不能同步。
- [ ] 重复提交不会产生重复实体。
- [ ] 网络失败可以重试。
- [ ] 版本冲突能被发现，已编辑日报不被静默覆盖。
- [ ] 密钥、令牌、原始会话、完整路径和文件内容不在同步载荷中。

## 8. 风险与约束

- Coding 工具的本地日志和 API 会变化。用适配器隔离，并做版本检测。
- Windows 桌面图标位置由系统 Shell 管理，精确恢复有兼容性风险。
- 模型 API 的参数和返回格式存在差异。统一接口要处理超时、限流、鉴权失败和空响应。
- 自动整理文件可能误操作，因此必须先预览、确认并保留操作历史。
- Android JNI 与 HarmonyOS NAPI 都还没有验证记录。鸿蒙桥接失败时改用 HTTPS，不把推测写成已支持。
- 同步涉及认证和冲突。Phase 4 之前不提供会让用户以为已经同步的界面状态。

## 9. 实现顺序

1. 阅读 ADR、本 PRD 和《技术设计文档》。
2. Phase 0 只做共享核心和测试。
3. Phase 1 只做 Windows MVP：应用壳、SQLite、任务、工作日志、日报、LLM Provider、Markdown 导出。
4. 然后再做 Android、HarmonyOS 和同步。
5. 桌面整理与 Coding 采集放在 Windows MVP 之后。
6. 每个阶段补充测试和运行说明。未实现的页面不能看起来可用。
7. 未经确认，不增加插件市场、微服务、自动删除或其他超出本文的功能。
8. 外部调用都要有超时、异常处理和用户可理解的错误。
9. 重要事实必须有来源。不确定结果标为待确认。
10. 阶段结束时列出已实现、未实现、实际测试结果、已知问题和下一阶段。
